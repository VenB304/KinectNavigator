## Current gesture model (v0.8 SWIPE + this session's changes)

### Left / Right / Up / Down — **segment-based swipe**
A swipe starts when one axis speed crosses `swipe_velocity` (1.3 torso/s) and dominates the
other by `swipe_axis_ratio` (1.4); vertical also needs the hand in front (`|ex| <
swipe_vert_x_band` 0.55) and in the y-band (`swipe_y_min -0.95 .. swipe_y_max 1.10`).

Once active, the motion is **split into segments at every direction reversal** (velocity
crosses ±`0.35 * swipe_velocity` opposite the current segment). Only the **current segment** is
judged, and its travel is measured **from the point the hand last turned around**
(`swSegStart = swSegExt`). So a small counter-flick ("countersteer") is just segment 1 (short
in the eventual direction, doesn't fire); the real stroke is segment 2, measured from the
turnaround, and fires ~2 frames in.

Fire needs, for the current segment: `>= swipe_min_frames` (2) frames, `progress >=
swipe_distance` (0.28 torso), still moving that way, and **peak speed this segment `>=
swipe_velocity * swipe_peak_ratio`** (1.82 torso/s — rejects a slow constant-velocity drift
like an arm lowering to rest). Aborts if `swFrames > swipe_max_active_frames` (24) or
`swSegs > swipe_max_segments` (4) or (vertical) the hand leaves the zone.

**A windup-hold on segment 1 was tried this session and REVERTED** — Ven said it made things
worse. Do not re-add `swipe_windup_frames` / `swipe_decisive_frac` / `seg1Held` without a
clear reason. The unsolved case: a counter-flick that is *itself* a full fast swipe-sized
stroke is genuinely ambiguous and will fire its own direction.

### L/R auto-repeat (hold arm out to the side)
After an L/R swipe, `RS_POST` for `post_swipe_ms` (400). Enter `RS_HOLD` if `armExt >
arm_extend_frac` (0.90) **and the arm is roughly horizontal** — new this session: `armLevel =
|Δy|/|Δx|` of hand-vs-dominant-shoulder, must be `<= arm_level_tan_max` (1.0 = ±45°). Exit if
`armExt < arm_relax_frac` (0.80) **or** `armLevel > arm_level_tan_max * 1.4` (hysteresis).
Repeat interval `repeat_first_ms` 430 → `repeat_min_ms` 200, step `repeat_accel_ms` 22.

### Confirm (Enter) — now **auto-repeats while held**
Pose: dominant hand raised (`ey > confirm_raise_fy` 0.05 — *very* low) + still (`|v| <
confirm_still_vel` 1.2), not mid-swipe, `rs == IDLE`, **and no Back pose active** (see below).
First fire after `confirm_dwell_ms` (1800) with `dwell_grace_frames` (20) tolerance. Then it
re-emits every `confirm_repeat_ms` (550) — first repeat delayed by `confirm_repeat_first_ms`
(900) as grace. Stops when the pose breaks or the hand drops below `confirm_raise_fy - 0.10`.
`confirm_repeat_ms = 0` restores one-shot.

### Back (Esc) — now **auto-repeats**, and **evaluated before Confirm**
Pose: non-dominant arm down-and-out to the side (`outFrac > back_out_min` 0.30,
`back_down_min` 0.22 `< downFrac <` `back_down_max` 0.88, `ndSpeed < back_still_vel` 1.2).
`back_dwell_ms` 1800, `back_repeat_ms` 550, `back_repeat_first_ms` 900.

**Fix this session for "I was trying to do Back and somehow got Confirm":** the Back block now
runs first, and while the Back pose is held it hard-disarms Confirm (`confirmArmed = true`,
`confirmSince` can't start). The dominant hand drifting up while you raise the other arm no
longer steals the gesture. If this still happens, next lever: raise `confirm_raise_fy` (0.05 →
0.20+) so a casual raise doesn't count as "raised".

### Gameplay mute (`suppress_in_game` default true)
Armed by the game's file I/O: `song_burst_count` (6) opens of the same `maps\<yr>\<song>_pc.ipk`
within `song_burst_ms` (1500), nothing else between. Mutes when `now - g_lastOpenTick >
file_idle_gameplay_ms` (9000) **and** `g_gameWndActive != 0` (new this session — game must be
foreground, `!IsIconic`, ≥ 640×400; a minimised/alt-tabbed game can't mute). On the
muted→unmuted edge `g_songLoadTick` is zeroed so a quiet menu can't re-mute.

Every mute on/off transition now logs:
`Gesture[t=..]: gameplay-mute ON/off  (lastOpen ..ms ago, songArm ..ms ago, wact=..)`.
The trace-line ` GAME` suffix is **dead code** (the mute path early-returns before the trace
print) — use the `gameplay-mute` log line instead.

## Trace line (kinectnav.ini `trace = 1`, ~15 Hz)

```
trace[t=..] ex= ey= evx= evy= ext= lvl= sw= sd= seg= pk= rs= stl= blk= swin= cf= bk=
```
- `ex ey` dominant hand pos rel SHOULDER_CENTER, torso units (+x = your right, +y = up)
- `evx evy` velocity, torso/s
- `ext` arm straightness (L/R repeat trigger); `lvl` arm angle `|Δy|/|Δx|` (small = horizontal)
- `sw` active swipe axis (0/1/2); `sd` current segment direction ±1; `seg` segment count;
  `pk` current-segment peak speed
- `rs` L/R repeat state (0 idle / 1 post / 2 hold); `stl` settle counter; `blk` swipe blocked;
  `swin` inside post-swipe settle window
- `cf` `bk` Confirm / Back dwell held ms

`GameProbe:` line (~1/s) has `wact=` (g_gameWndActive) and `open/s=`. `gameplay-mute ON/off`
logs on every mute transition.
