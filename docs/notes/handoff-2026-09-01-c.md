## Current recogniser — the air d-pad  (`nav_model = extend`, the compiled default)

All in `src/SkeletonKey/gestures.cpp` — `ExtendUpdate()` + `struct ExtendState eg`, a
**second, self-contained recogniser path** (own dt, own 1€ filter). `Gestures::Update()`
branches on `c.navModel != 0` right after the torso check; `swipe` = 0 keeps the old model.

**Model:** hand position `(ex, ey)` = 1€-filtered dominant hand **minus the dominant
shoulder**, torso units, `mirror`-applied. `r = |(ex,ey)|`.

- **Park box** — `r < dpadParkRadius` (0.32). Home/off. Exit at `*dpadParkExitK` (1.35),
  hysteresis. Wedge/fire logic is skipped while parked.
- **Clutch** — `eg.armed` starts **false**. Park the hand for `dpadArmDwellMs` (200) → armed.
  Auto-disarm: `armed && !parked && wedge==0` (no-man's-land) for `dpadDisarmMs` (1500) →
  `armed=false`, occupancy cleared. `dpad_arm=0` disables the clutch (always live). Logs
  `dpad ARMED` / `dpad disarmed (idle Nms)`.
- **Wedges** (component tests on ex/ey, no atan2): RIGHT `ex>0 && |ey|<=|ex|*tan(halfDeg)`;
  LEFT mirror; UP `ey>0 && |ex|<=|ey|*tan`; DOWN `ey < -dpadDownMinDrop(0.25) && |ex| >=
  dpadDownMinOut(0.30) && |ex|<=|ey|`. `dpadWedgeHalfDeg` 24. **Straight-down and the gaps
  between wedges are dead** → a hanging arm is ignored. Distance past the park box does not
  matter.
- **Fire/repeat (nav)** — enter a wedge, `dpadEntryDebounce` (3) frames → single arrow key.
  Hold past `dpadRepeatDwellMs` (600) → auto-repeat `dpadRepeatFirstMs` 430 →
  `dpadRepeatMinMs` 200 (step `dpadRepeatAccelMs` 22). `dpadWedgeGraceFr` (4) tolerates a
  jitter blip into a dead gap.
- **Command mode** — non-dom hand within `dpadCmdGateRadius` (0.42, exit `*dpadCmdGateExitK`
  1.5, sticky `eg.cmdOn`) of the non-dom shoulder. While gated: wedge up/right → **Enter**
  after `dpadCmdDwellMs` (600); wedge down/left → **Esc** after `dpadBackDwellMs` (**3000**).
  Then slow repeat `dpadCmdRepeatMs` (700). Nav suppressed. Occupancy id = `(cmd<<3)|wedge`;
  a **mode flip while the same wedge is held** → `suppressed`, emit nothing until the wedge
  is left (so dropping the left hand mid-Confirm doesn't fire a stray arrow).

**Overlay** (`overlay.cpp`, `d.dpadMode` branch): field square + crosshair, park box, R/L/U/D
labels (live wedge lit), hand marker (grey parked / cyan nav / magenta command),
`ASLEEP`/`READY` banner, `L hand → shoulder  0.34 / 0.42` gate readout, `CONFIRM/BACK nn%`
dwell bar, action flash. `GestureDebug` carries `dpad*` fields.

**Trace** (`trace = 1`): `dpad[t=..] ex= ey= r= arm= park= w= cmd= nd= cdw= occf= fired= rep= <tag>`
~15 Hz. Also `Gesture[..]: dpad RIGHT` / `dpad CONFIRM [cmd]` / `... (repeat N)` fire lines.

**In-game status:** Ven — "works so much better, got into the dance." Nav wedges good.
The 3 s Esc + the wider left-shoulder gate + the clutch all landed this session and are
deployed but only lightly tested. No felt gripes outstanding.

## Signal conditioning (`filter.h`, both models)

1€ filter (Casiez) on the raw dominant-hand position → `f1eX/f1eY`; 5-point Savitzky-Golay
first-derivative → `sgVx/sgVy`. Kills the >16 torso/s inferred-joint spikes, ~2-frame
(~66 ms) lag. The d-pad uses mostly the 1€ **position**; the swipe path runs its whole
trigger/segmentation on the SG velocity. `filter_1e_min_cutoff` 1.0, `filter_1e_beta` 0.05.
