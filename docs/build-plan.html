The idea

Pose in, keystroke out

The mod's menus already take WASD/arrows, Space/Enter, and Esc/Backspace. Skeleton Key watches the Kinect skeleton the game is already receiving, recognises a small set of deliberate gestures, and synthesises those exact keys — so a dancer can pick a song, confirm, and back out without touching a keyboard or phone.

It ships as a single drop-in Kinect10.dll that sits between the game and whatever real Kinect back-end is in use. It adds a feature; it replaces nothing.

Architecture

One shim, two kinds of user

The same middle layer works whether the skeleton comes from real Kinect hardware or from ItsVexor's webcam emulator. Skeleton Key forwards the eight functions the game imports to a renamed back-end DLL, and taps the one method that carries body data.

Evidence from the binaries

How the hook attaches

Legacy.exe is 32-bit and imports Kinect10.dll by ordinal only — eight functions. ItsVexor's fake DLL exports exactly the same eight, which confirms the surface we need. The game drives the sensor through the INuiSensor COM interface (the fake DLL logs interface-only methods like NuiSkeletonTrackingEnable), so our tap point is the vtable method, not the flat export.

Because there is only ever one process talking to the sensor — the game — the v1 "two apps can't share one Kinect" problem never arises. The recognizer is a passenger on data the game already pulls.

Implementation detail

Shim mechanics

Everything below lives in one x86 DLL built Release | Win32, /MT (static CRT, no redistributable needed). All eight exports are hand-written __stdcall thunks with the exact SDK 1.8 NuiApi.h signatures; none link against Kinect10.lib, they call function pointers resolved from the back-end at runtime.

Startup — lazy, never in DllMain

DllMain only calls DisableThreadLibraryCalls and stores the module handle. LoadLibrary under the loader lock is unsafe, so real init runs behind InitOnceExecuteOnce, triggered by whichever of our eight exports the game calls first:

  1. Resolve the back-end. LoadLibraryW("Kinect10_backend.dll") from our own directory; GetProcAddress all 8 functions by name into a struct of pointers. Null → log fatal, show one message box, let thunks return E_NUI_DEVICE_NOT_CONNECTED.
  2. Load config. kinectnav.json beside the DLL; if absent, write the default and continue. Record its mtime for hot-reload.
  3. Allocate the frame buffer (below) and create the recognizer thread suspended-idle — it blocks until the first frame is published.

The vtable wrap — fallback only

M1 showed this is not needed: the game calls the flat NuiSkeletonGetNextFrame export directly, so M2 taps the frame inside that thunk (copy after forwarding, de-dup by frame number). The vtable wrap below stays documented as the fallback if a future Legacy build switches to the interface method.

The game would call NuiCreateSensorByIndex(0, &pSensor), then invoke methods on pSensor through its COM vtable. We patch one slot of that shared vtable, once:

// our export, ordinal 6
HRESULT __stdcall NuiCreateSensorByIndex(int i, INuiSensor** ppSensor) {
    EnsureInit();
    HRESULT hr = g_be.NuiCreateSensorByIndex(i, ppSensor);
    if (SUCCEEDED(hr) && *ppSensor && !g_origGetNextFrame) {
        void** vtbl = *reinterpret_cast<void***>(*ppSensor);
        void** slot = &vtbl[SKEL_GETNEXT_SLOT];      // fixed for SDK 1.8
        g_origGetNextFrame = (GetNextFrameFn)*slot;
        DWORD old;
        VirtualProtect(slot, sizeof(void*), PAGE_READWRITE, &old);
        *slot = (void*)&Hook_SkeletonGetNextFrame;
        VirtualProtect(slot, sizeof(void*), old, &old);
    }
    return hr;
}

// runs on the game's Kinect thread
HRESULT __stdcall Hook_SkeletonGetNextFrame(
        INuiSensor* self, DWORD wait, NUI_SKELETON_FRAME* out) {
    HRESULT hr = g_origGetNextFrame(self, wait, out);
    if (SUCCEEDED(hr) && out) g_frames.publish(*out);   // ~2 KB memcpy
    return hr;
}

SKEL_GETNEXT_SLOT is the method's index in INuiSensor, counted from the header — stable for SDK 1.8. M2 verifies it: a wrong slot yields garbage or a bad HRESULT immediately. Fallback if in-place patching proves fragile: return a full proxy object whose vtable forwards every INuiSensor method to the real one. More code, no VirtualProtect.

Our flat export #17 also forwards-and-taps, for the case where the game uses the flat API too; frames are de-duplicated by timestamp so the recognizer never sees one twice.

Frame buffer

Single producer (game Kinect thread), single consumer (recognizer). A small array of 8 NUI_SKELETON_FRAME slots behind an SRWLOCK — 30 Hz, ~2 KB per copy, contention is nil so a lock is simpler than lock-free and safe. Consumer reads the newest slot each tick and drops anything it fell behind on. publish() also signals a condition variable the recognizer waits on, so it never polls.

Teardown

NuiShutdown (#16) and DLL_PROCESS_DETACH: set the stop event, WaitForSingleObject(thread, 500), then forward to the back-end's NuiShutdown. Leave the vtable patch in place (the DLL stays resident) but clear g_origGetNextFrame so a later re-create re-patches. FreeLibrary(backend) only on detach.

Interaction model — hybrid

Gesture vocabulary

Six actions cover menu navigation. Every trigger requires a return to a neutral pose (arms relaxed at sides) before it can fire again, plus a per-action cooldown of roughly 450 ms. All thresholds live in config.

ActionGestureDetection sketchKeys sent
Left / Right Horizontal hand swipe, hand above hip hand X-velocity over threshold for ≥3 frames, net X displacement past swipeDist, then must stop or reverse ← / → (A / D)
Up / Down Vertical hand swipe same rule on the Y axis; weakest detector — see recognizer notes ↑ / ↓ (W / S)
Confirm Dwell — hold either hand still in a small zone ~1.2 s (default) joint position variance under dwellJitter across the window; progress shown by beep cadence Enter (or Space)
Confirm Push hand toward sensor (opt-in, real Kinect only) hand Z toward sensor past pushVel, elbow extending; off by default because webcam depth is unreliable Enter
Back Static pose — both hands on hips, elbows flared, held ~600 ms both wrist-to-hip distances under threshold and elbows outside shoulders, held Esc (or Backspace)

mirror flips Left/Right for dancers who read the sensor image as a mirror. There is no separate "start song" action — Confirm advances through coach select into the routine, matching the keyboard.

Implementation detail

Recognizer design

Skeleton space

SDK 1.8 gives NUI_SKELETON_FRAME with up to 6 NUI_SKELETON_DATA. Each has a tracking state (NOT_TRACKED / POSITION_ONLY / TRACKED), a tracking ID, and 20 joints as Vector4 in metres, right-handed: +X to the sensor's left, +Y up, +Z out toward the room. A person's raised right hand therefore moves in −X — which is exactly why mirror exists. Per-joint state (NOT_TRACKED / INFERRED / TRACKED) is checked for every joint a detector reads.

Joints used: HAND_L/R (fall back to WRIST_L/R), ELBOW_L/R, SHOULDER_L/R, SHOULDER_CENTER, HIP_CENTER, HIP_L/R, HEAD. Webcam-sourced skeletons fill the same 20 slots but Z is approximate and some joints sit permanently INFERRED — allowed, but they cap a detector's confidence at 0.7.

Choosing the navigator

  1. Candidates = skeletons with state TRACKED. None → recognizer idles, emits nothing, notes "no body".
  2. Score = smallest Position.z (closest); tie-break smallest |Position.x| (most centred).
  3. Sticky: keep the same tracking ID until it is lost for >0.5 s, even if someone else steps closer — stops the cursor ping-ponging between two dancers.

Normalisation & smoothing

Work body-relative so gestures are position- and size-independent. Let SC = shoulder-centre, HC = hip-centre, torso = |SC−HC| (~0.5 m adult). A hand's working coordinate is p = (HAND − SC) / torso — dimensionless. Each used joint gets exponential smoothing s = a·raw + (1−a)·s_prev, fast track a = 0.5 for motion, slow track a = 0.15 for the neutral test and velocity baselines. Per-frame dt comes from the frame timestamp, never assumed 33 ms.

Debounce state machine

IDLE_NO_BODY → NEUTRAL → ARMED → EMIT → COOLDOWN → back to NEUTRAL.

  • NEUTRAL — both hands hanging at sides (p.y < 0.15, |p.x| in [0.4, 1.0]), held neutralHoldMs (200). This is the "return to neutral between triggers" rule.
  • ARMED — all detectors live. First to clear its threshold at confidence ≥ minConfidence (0.6) wins; ties resolve Back > Confirm > Swipe.
  • EMIT → send keys, enter COOLDOWN for cooldownMs (450), all detectors ignored.
  • After cooldown, NEUTRAL must be re-entered before the next emit. Optional allowHoldRepeat: while a hand stays past the swipe end-zone, re-emit the same direction every repeatMs (350) without a neutral return — for scrolling long song lists. Off by default.
  • Body lost >0.5 s → reset to IDLE_NO_BODY. First 15 frames after re-acquiring a body are ignored while smoothing settles.

The one nasty overlap: arms relaxed at the sides put the hands near the hips too — almost the Back pose. The elbow-flare requirement (akimbo shape) is what separates "I'm resting" from "I want to go back". Vertical swipes are the weakest detector because raising or lowering an arm looks like one; if tuning can't make them reliable, the fallback is a verticalMode: "handZone" where a hand parked in an upper zone repeat-emits UP.

Output

Action → virtual-key from keys config. SendInput with a key-down, keyPressMs (40) hold, key-up. The game polls with GetAsyncKeyState, so VK-based injection is the right call; a scancode variant and a PostMessage(hwnd, WM_KEYDOWN/UP) path (window found by our own PID) are the fallbacks. Keys are sent only while the game window is foreground unless requireForeground:false.

M1 — "Passthrough proxy" task list

Goal: our Kinect10.dll in the game folder, game runs identically, Kinect scoring works, every call logged. No gestures, no input, no vtable patch yet.

  1. Solution + DLL project, Release|Win32, /MT, output name Kinect10.dll.
  2. exports.def with the 8 ordinals (bare names + @N). Confirm with dumpbin /exports that the build shows ordinals 5, 6, 9, 16, 17, 21, 22, 26.
  3. backend.cpp: on InitOnce, LoadLibraryW("Kinect10_backend.dll"), GetProcAddress all 8 by name, assert non-null, log module path + addresses.
  4. exports.cpp: all 8 as __stdcall thunks with exact SDK signatures. Each logs "[call] NuiXxx(...)" and its HRESULT, then tail-calls the back-end pointer. For the two CreateSensor functions, also log the returned INuiSensor* value.
  5. log.cpp: append to SkeletonKey.log beside the DLL, one line per call, HH:MM:SS.mmm tid=... msg, flush each line.
  6. install.bat: back up folder → verify Kinect10.dll is the genuine one (size / version marker) → ren Kinect10.dll Kinect10_backend.dll → copy ours in → copy kinectnav.default.json to kinectnav.json.
  7. Test: launch Legacy.exe → no crash, no missing-DLL error → controller select shows Kinect Sensor, selectable → start a song with the real sensor → scoring and feedback identical to stock → uninstall.bat restores stock.
  8. Exit criteria: 30-minute session, zero regressions vs. stock, log shows NuiGetSensorCount → NuiCreateSensorByIndex (non-null sensor) → a stream of frame calls during play.

Tooling — record / replay harness (built 28 Aug)

A record.flag next to the shim makes it append every tapped frame to skcap-*.skcap. SkeletonKeyReplay.exe feeds a capture back through the same framebuffer.cpp + recognizer.cpp the DLL ships — --step runs it fast and lossless, --speed N paces from liTimeStamp. So the recognizer is now built and tuned offline against captured sessions, with only occasional live checks. The recognizer's clock was moved onto frame.liTimeStamp for this to be faithful. A first real capture (~230 s, an 83 s scripted gesture run) is banked.

Known unknowns

Risks & mitigations

Resolved · M1

Frame cadence on menu screens. M1 on real hardware showed a constant ~30 Hz poll on every screen — title, controller select, song list, coach, gameplay — with no stalls. The recognizer will always have fresh frames.

Resolved · M1

Flat export vs. vtable method. M1 confirmed the game calls the flat NuiSkeletonGetNextFrame export directly. No vtable patch, no SKEL_GETNEXT_SLOT to get right — M2 just copies the frame inside the export thunk.

Handle in M2

Game hard-exits on quit. M1 saw no NuiShutdown call and no graceful DLL detach — the process just terminates.

Mitigation: the recognizer thread must carry no exit-flush obligation. Persist nothing that matters only at shutdown; let the OS reclaim the thread.

Confirmed · M2

Hand depth (Z) is unreliable — not just for webcam users. M2 showed a real Kinect v1 reports hands as Inferred most of the time, with Z bouncing ~0.3 m frame to frame.

Resolution: “push to confirm” is dropped entirely. Confirm is dwell-only (a pure X/Y test). All hand-based detectors accept Inferred joints and smooth hard.

Tuning risk

Vertical swipes vs. arm raises. Raising or lowering an arm reads like an up/down swipe.

Mitigation: down-swipe must start from a raised position; if still unreliable, switch verticalMode to handZone (parked hand repeat-emits).

Open question

Where does this actually get played? M2 and the first capture were recorded in a cramped room at marginal distance. If the real setting is a cleared space that noise is pessimistic; if it is that same room, that noise level is the tuning target. Still unanswered.

The record / replay harness is now built, so this matters less for iteration — but the final tuning pass should use a capture from wherever it will really be played.

Note

Two DLL variants ship in ItsVexor's zip. JDLEGACY is x86 and matches this game build; DREYN is x64 for a different 64-bit Legacy build and will not load here. Test against the x86 one.

Prior art on the drive

What "Legacy Sensor by ItsVexor" taught us

It is a webcam-to-Kinect emulator for this exact mod: a PyInstaller bundle running OpenCV + MediaPipe Pose that infers a body skeleton from a normal camera, writes joint frames to shared memory, and serves them to the game through a small replacement Kinect10.dll. Replacing the real DLL is also what unlocks the "Kinect Sensor" choice on the controller screen.

It confirmed three things we were otherwise guessing: the DLL-replacement hook works on this build in the wild, the exact eight-ordinal export surface, and that the game uses the INuiSensor interface path. Its shared-memory + events + SRW-lock IPC is a reference if Skeleton Key ever needs its own sensor feed. Collaboration is not being pursued — this is an independent tool.
